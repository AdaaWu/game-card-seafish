## 1. 總評

**素材層（卡圖、卡框、圖示、對戰背景）已經是手繪水彩；落差全部集中在「容器」：按鈕、面板、標題、節點、場上生物仍是 CSS 色塊與系統元件**

- 三個最大落差
  - **角色存在感不足**：劇情彈窗頭像 120px、自由對戰 96px、地圖節點只有數字、主選單沒有角色。角色是這款遊戲最強的資產，卻只在對話時出現
  - **容器沒有材質**：所有按鈕、面板是純色圓角矩形，跟卡框 a 套的紙紋與陣營花紋不是同一個世界
  - **場上生物是橢圓頭像**：與手牌卡面語言不一致，狀態全靠小圓點圖示，6 格擺滿時辨識度低
- 本輪做法
  - 出一套共用 UI kit（按鈕、面板、標題組、地圖、設定、生物外觀），全部用九宮格切片，程式只換 `border-image` 與 token
  - 所有角色圖尺寸改成 `clamp` 或 `vh`，桌機與手機橫向分開給值

## 2. 各畫面最重要的 3 條

- **標題**（`01-title-*`）
  - 手機橫向「點擊任意處開始」仍被擠出畫面（U-T1，延續上一輪 #9）
  - 主角圖 260px 只佔畫面高 29%，應放大到 46vh（U-T2）
  - 標題字是黑體加粗描邊，等 Logo 前先套共用標題組（U-T3）
- **主選單**（`02a-menu-locked-*`、`02c-menu-hover-*`）
  - 按鈕外框是純色圓角矩形，hover 用 `scale(1.04)`，違反「狀態只改顏色光暈」原則（U-M1）

## 6. 場上生物外觀重新設計

### 6.1 現況評估

**橢圓頭像框是唯一沒有跟著卡框改版的元件，狀態疊在一起時只剩顏色在溝通**

- 截圖：`04f-board-mid-1440x900.png`、`04f-board-mid-844x390.png`、狀態對照 `04g-minion-states-gallery.png`
- 實作：`web/src/render/battle/minionTexture.ts` 以 Canvas 畫橢圓（守護改貝殼盾形），數字與關鍵字圖示畫進同一張貼圖；冰凍、泡泡、可攻擊是 `Battlefield.ts` 另外疊的 Mesh
- 辨識度
  - 插畫被裁進橢圓，寬型物種（鯨、魟）只剩中段
  - 1440 下每隻約 90px、手機約 50px，角色細節看不出
- 與手牌一致性
  - 手牌是方形卡框加陣營花紋與紙紋；場上是平塗漸層加粗描邊，像兩套遊戲
- 數值可讀性
  - 攻血徽章是程式畫的星形與愛心，比手牌的四角圖示粗糙
  - 手機上數字約 12px 高，加上 8px 描邊，6 和 8、1 和 7 容易混
- 狀態表現
  - 守護：外形從橢圓變盾形，單看可分，但盾形與受傷裂痕、關鍵字圓點擠在上緣
  - 潛藏、泡泡盾：只有頂部 20px 小圓點圖示，手機上看不出
  - 冰凍：半透明白色矩形蓋住整隻，與泡泡盾外罩疊在一起時兩層白色分不開
  - 可攻擊：腳下柔光，敵我同色系背景上偏淡
  - 已攻擊：沒有任何表現，只能靠可攻擊光消失推論
  - 受傷：生命數字變紅加一條裂痕線，裂痕畫在愛心右上角，常被關鍵字圓點蓋住
  - 增益：數字變綠，可辨認
- 疊加：「守護＋潛藏＋泡泡＋突襲＋吸血」時上緣 4 顆圓點加「+2」，只能點開細節卡才知道

### 6.2 設計方向

- **A 拱窗小卡（選定）**
  - 做法：上方拱形插畫窗、下方攻血底座，外框沿用卡框 a 套的陣營色與花紋
  - Pros
    - 與手牌同一語言，玩家出牌後一眼認得是同一張卡
    - 每種狀態都有固定的外框位置可依附：守護在外環、冰凍在框內四邊、泡泡在最外層、已攻擊在窗內
    - 插畫窗比橢圓多約 30% 面積
  - Cons
    - 比橢圓高約 8%，要重排雙方兩列的垂直間距
    - 切片多（每陣營外框與窗底各一張），貼圖記憶體增加
  - 6 格與手機：桌機 120 寬時數字約 26px 高；手機 80 寬時約 16px 高，均可讀
- **B 圓形徽章**
  - Pros：最省空間，手機上 6 格最寬鬆；與英雄頭像同形，層級感強
  - Cons：插畫裁切最多；守護外環、泡泡盾都是圓，疊加時分不開；與手牌不一致
  - 6 格與手機：可讀，但狀態辨識最差
- **C 貼紙加底座**
  - Pros：最可愛，直接用角色貼紙白邊，最貼近 art-style.md 的貼紙 DNA
  - Cons：沒有外框，冰凍與守護只能畫在角色輪廓外，會跟白色 die-cut 邊打架；不同物種輪廓差很大，攻血位置不固定
  - 6 格與手機：寬型物種會壓到隔壁格，手機上不可行
- 對照圖：`assets/pending/batch-20261023-ui/_preview/minion-directions.png`

### 6.3 選定規格

  - 守護：扇貝外環，形狀差異，色弱也能辨認
  - 潛藏：薰衣草霧紗加插畫透明度 55%
  - 泡泡盾：最外層泡泡外罩，數字底座疊在泡泡之上
  - 冰凍：冰晶框貼著外框內側
  - 可攻擊：外框綠光，透明度 0.7 到 1.0 循環 1.6 秒

### 6.4 程式端接法

**建議改成 sprite 分層：靜態部分烘成一張 CanvasTexture，狀態層用共用材質的獨立 Mesh，透明度動畫不必重畫貼圖**

- 底層貼圖（CanvasTexture，依外觀快取，沿用 `MinionTextureCache` 參照計數）
  - 內容：`minion-window-<陣營>` + 插畫（窗形遮罩）+ `minion-frame-<陣營>` + `minion-statplate` + 攻血圖示 + 數字
  - 尺寸：576 x 704（2x 畫布），比現行 384 x 480 大 2.2 倍；場上 12 隻加快取約 25MB GPU，可接受
  - 切片以 `Image` 預載一次，`drawMinion` 內 `drawImage` 疊上，不再用 Path2D 畫框
  - 快取鍵維持 `cardId|attack|health|maxHealth`，但移除 `keywords`（狀態改走獨立層），快取命中率提高
- 狀態層（每種一個共用 `MeshBasicMaterial` + 共用 `PlaneGeometry`，所有生物共用，draw call 增加但沒有新貼圖）
  - `ready`：`minion-ready` 貼圖，取代現行 `radialTexture` 腳下光，`frame()` 內只改 `opacity`
  - `taunt`：`minion-taunt`，`renderOrder` 低於底層
  - `exhausted`：`minion-exhausted` 疊在底層上，同時把底層材質 `color` 設成 `0xb8b2bf` 達到去飽和感
  - `stealth`：`ov-stealth`，同時底層 `opacity = 0.55`
  - `frozen`：`ov-frozen` 取代現行 `iceMat`
  - `bubble`：`ov-bubble` 取代現行 `bubbleMat`，`renderOrder` 高於數字層時要把數字拆到最上層 Mesh；建議數字留在底層貼圖、泡泡 `opacity: 0.85`，簡單且足夠
- 尺寸
  - `MINION_W` 由 `px(140)` 改 `px(160)`，`MINION_H` 依 288 x 352 比例
  - 手機另給 `compact ? px(222) : px(160)` 讓實際顯示約 80px；`battleLayout.ts` 的 `ROW_OFFSET` 與手牌 `handTop` 要一起驗證
- 動態限制
  - 只允許 `ready` 透明度循環與受擊閃白（現有）；不加待機浮動、不加呼吸縮放
  - `bob` 子層維持不做待機漂浮
- 切片載入：`uiImageUrl('minion/minion-frame-leaf', true)`，與卡框同一套 `assetUrls`
